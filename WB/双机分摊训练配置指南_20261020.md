## 0. 结论先行

| 方案 | 墙钟时间 | 磁盘需求 |
|---|---|---|
| 单机 3 折（现状） | **约 38 小时** | 3 折缓存 86.5 GiB，**当前装不下** |

本机（A，RTX 4060 Laptop 8GB）E 盘现剩 **70 GB**，而每折缓存 28.8 GiB。**三折缓存根本放不下**——所以双机不只是提速，也是继续跑下去的前提。

推荐分配（按实测速度定，见 §5）：

- **A**：fold0（已在跑，21:12 训练缓存已完成）→ 接着 fold1

## 1. 为什么不能「把整个目录拷过去」

这套工程有 5 个硬约束，任何一条踩中都会在启动时报错或产出不可比的折。先理解，再动手。

### 1.1 审计指纹含文件修改时间 → 必须重新绑定

`glaucoma/data.py:62` 的 `local_fingerprint` 由「CSV 的 sha256 + 每个文件的 size + **mtime_ns**」构成，`require_audit` 会严格比对。文件一复制，mtime 全变，必然报：

> `Local files/CSV changed or audit format is old; rerun audit or import-audit`

**官方解法是 `import-audit`**（`glaucoma/handoff.py:14`）：它逐张校验 63,100 张图的 size + sha256，然后只重绑 `local_fingerprint`，**保留可移植的 `data_fingerprint` 和 `fold_fingerprint`**。所以折划分、数据身份在 B 上是一致的，只有本地时间戳被重新盖章。

### 1.2 数据路径是硬编码的

`scripts/plan3_local.py:92` 写死 `ROOT/'glaucoma_first'`。所以 B 上数据**必须**位于 `<项目根>/glaucoma_first`，不能用别的位置再指过去。

### 1.3 资格门会校验 4 项，B 必须自己测速

`scripts/plan3_local.py:58-61`：

```python
if (qualified['qualified'] is not True or qualified['code_sha256'] != code_hash()
        or config != qualified['selected_config']
        or job['workers'] != qualified['chosen']['local']['workers']):
    raise ValueError('This code/configuration/workers did not pass real execution qualification')
```

- `code_sha256` = `plan3/*.py` 的哈希 → 代码必须逐字节一致
- `config` → 必须与该机资格报告里选中的配置完全一致
- `workers` → 必须等于该机实测选出的读取进程数
- `pretrained_sha256` → 权重必须一致

**结论：不能把 A 的 `qualification.json` 直接抄给 B。** B 的 workers 和速度是它自己硬件上的实测值，必须重跑一遍资格链（约 85 分钟）。

### 1.4 断点续跑身份绑定机器 → 折不能跨机迁移

`local_execution.json` 里记录了 `runner_sha256`、`torch_threads`、`runtime: versions()`。`--resume` 要求这份身份完全一致。所以**跑到一半的折不能换机器续跑**，切分只能按整折。

### 1.5 最隐蔽的一条：micro-batch 由测速决定，会导致三折不可比

`scripts/qualify-plan3-speed.py:93`：

```python
candidate = {**base, 'batch_size': selected[0], 'accumulation': 32//selected[0],
             'gradient_checkpointing': selected[1], ...}
```

配置里的 `batch_size` / `gradient_checkpointing` 是**从该机测速结果里选出来的**。A 的 8GB 卡选了 `b4 + gc`。如果 B 是 12GB/16GB 卡，很可能选出 `b8`——虽然有效批量仍是 32、`validate_config` 照样通过，但**训练动态不同，fold2 和 fold0/fold1 就不是同一个配方，三折 OOF 拼不到一起**。

**这是反直觉的：B 的卡更强，反而可能毁掉可比性。**

为此我已经给两个脚本加了「钉住配置」能力（向后兼容，默认行为不变）：

```bash
--pin-config configs/plan3/rfm448-local-speed-v2.json
```

它会把候选集限制在 A 已选中的 `(batch_size, gradient_checkpointing)` 那一档，只用 B 自己的 workers 和速度。已在本机实测验证：

- 正向：钉住后仍选中 `resized_cached_w2_b4_gc`，生成的 `candidate-config.json` 与现用配方**逐字段相同**
- 反向：钉成 `b16` 时报错 `Pinned micro-batch 16 / gradient_checkpointing=True did not pass this machine's real measurements; do not mix recipes across folds`

如果 B 的卡连 `b4+gc` 都跑不动（显存 < 6GB），钉住会直接失败——**这时候正确的做法是换机器，不是放宽配方**。

## 4. 分步操作（在机器 B 上执行）

### Step 1 · 建立目录布局

```
D:\computer_competition\          ← 项目根（盘符随意，路径不限）
├── glaucoma_first\               ← 数据集（33GB）
├── weights\
├── configs\  plan3\  scripts\  glaucoma\  tests\  run.py
└── artifacts\
    ├── audit\                    ← 由 import-audit 生成
    ├── plan3_inputs\
    └── plan3_cache\              ← 训练时自动建
```

根路径可以是 `D:\` 或 `F:\`，**不影响任何指纹**（`local_fingerprint` 与 `data_fingerprint` 都不含绝对路径）。

### Step 2 · 拷贝代码

在 **A** 上执行（`B_HOST` 换成 B 的机器名或 IP）：

```bash
robocopy E:\computer_competition \\B_HOST\D$\computer_competition /E ^
  /XD .git .venv .venv-check .cache __pycache__ artifacts glaucoma_first handoff WB ^
  /XF *.zip *.pt *.pth
```

这一步会把未提交的 `plan3/`、`configs/plan3/`、`scripts/` 一起带过去——**不能只 `git clone`**，因为关键改动都还没提交。

### Step 3 · 拷贝数据

```bash
robocopy E:\computer_competition\glaucoma_first \\B_HOST\D$\computer_competition\glaucoma_first /E /MT:16
```

33 GB，千兆网约 45–60 分钟。也可以直接拷贝 `glaucoma_first.zip`（33.24 GB）过去再解压。

> 注意：**不要**顺手把 A 的 `artifacts/plan3_cache` 拷过去，那是 fold0 的行集，fold2 用不上。

### Step 4 · 拷审计目录与其余小文件

```bash
robocopy E:\computer_competition\artifacts\audit \\B_HOST\D$\sync\audit /E
robocopy E:\computer_competition\artifacts\plan3_inputs \\B_HOST\D$\computer_competition\artifacts\plan3_inputs /E
robocopy E:\computer_competition\weights \\B_HOST\D$\computer_competition\weights /E
```

审计目录故意放在 `D:\sync\audit`——`import-audit` 要求 source 与 output **不是同一个目录**。

### Step 5 · 建环境

```powershell
cd D:\computer_competition
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
```

必须严格按 `requirements.lock.txt`（`torch==2.10.0+cu128`、`timm==1.0.24`、`numpy==2.5.2`）。版本漂移会改变确定性行为和速度，进而影响资格判定。

验证：

```powershell
.\.venv\Scripts\python.exe run.py environment
```

### Step 6 · 重新绑定审计指纹

```powershell
.\.venv\Scripts\python.exe run.py import-audit --source D:\sync\audit --workers 16
```

它会逐张校验 63,100 张图，打印 `import-audit verified N/63100`，最后输出 `Imported identical data and folds: 917ca8a7...`。

**校验 `data_fingerprint` 必须是 `917ca8a7f765b7b915d25beb1db2f68202707765185b0db15706d27163779d52`**，`fold_fingerprint` 必须是 `30cf96edc5a0bdfa80fbd1fd92b21674b317bb39529de65ce3fa613eec6f0606`。不一致就说明数据传坏了，停下来重传，不要继续。

### Step 7 · 跑资格链（约 85 分钟）

先做确定性配对诊断（约 5 分钟）：

```powershell
.\.venv\Scripts\python.exe scripts\plan3-local-profile.py --diagnose-only ^
  --output artifacts\plan3_speed_20261020\determinism-diagnostic.json
```

然后一条命令跑完 测速矩阵 → 512 图独立验证 → 跨进程恢复对照 → 资格判定 → 生成 fold2 作业：

```powershell
.\.venv\Scripts\python.exe scripts\finish-plan3-local-qualification.py ^
  --fold 2 ^
  --pin-config configs\plan3\rfm448-local-speed-v2.json ^
  --qualify-only
```

- `--fold 2`：作业写 `fold: 2`，输出到 `artifacts/plan3/pilot400-rfm448-local-speed-v2-f2`
- `--pin-config`：锁定 A 的 micro-batch 与梯度检查点设置，保证三折同配方
- `--qualify-only`：**跑到生成作业就停，不自动开训**。这一步很关键——不加这个参数会直接开始训练，等于跳过你的检查

跑完后确认 `artifacts\plan3_speed_20261020\qualified\qualification.json` 里 `"qualified": true`，且 `selected_config` 与 A 的 `configs/plan3/rfm448-local-speed-v2.json` 在 `model/size/batch_size/accumulation/gradient_checkpointing/preprocess_version` 六项上完全一致。

### Step 8 · 启动训练

```powershell
.\.venv\Scripts\python.exe scripts\plan3_local.py ^
  --job artifacts\plan3_speed_20261020\local-fold2-job.json ^
  --qualification artifacts\plan3_speed_20261020\qualified\qualification.json ^
  --continue-until-complete
```

`--continue-until-complete` 会自动处理 10 小时会话上限：每段会话到点退出，然后从**最后一个完整轮**续跑，最多 30 段，直到 `status.json` 的 `complete` 为 true。

建议挂后台并留日志：

```powershell
New-Item -ItemType Directory -Force artifacts\plan3_speed_20261020 | Out-Null
Start-Process -FilePath .\.venv\Scripts\python.exe `
  -ArgumentList 'scripts\plan3_local.py','--job','artifacts\plan3_speed_20261020\local-fold2-job.json','--qualification','artifacts\plan3_speed_20261020\qualified\qualification.json','--continue-until-complete' `
  -RedirectStandardOutput artifacts\plan3_speed_20261020\fold2.log `
  -RedirectStandardError  artifacts\plan3_speed_20261020\fold2.err.log `
  -WindowStyle Hidden
```

## 5. 折怎么分配

三折里 A 已经占了 fold0（21:12 训练缓存刚建完，即将进第 1 轮）。剩下 fold1、fold2 按 **B 的实测速度**决定：

| B 的稳态速度 | 分配 | 理由 |
|---|---|---|
| > 24.95 张/秒（比 A 快） | A = fold0；B = fold1 + fold2 | 快机吃两折，A 提前收工 |
| ≈ 24.95（同档） | A = fold0 + fold1；B = fold2 | 均衡，各约 24h / 12h |
| < 24.95（比 A 慢） | A = fold0 + fold1；B = fold2 | 慢机只给一折 |

B 的稳态速度看 `artifacts/plan3_speed_20261020/qualified/qualification.json` 里的
`chosen.local.steady_images_per_second`。

**单折耗时估算**：24 轮 × 单轮时间，A 上单轮外推 29.9 分钟 ≈ **12 小时/折**。因为会话上限 10 小时，每折实际会经历一次"10h + 续跑"，末轮不完整会被丢弃重做，实际约 **12.5–13 小时/折**。

**时间线（今晚开工）**

| 机器 | 任务 | 预计完成 |
|---|---|---|
| A | fold0 | 明天 ~09:30 |
| A | fold1 | 明天 ~22:00 |
| B | 准备（传数据+环境+资格） | 明天 ~00:00 |
| B | fold2 | 明天 ~12:30 |

双机总墙钟约 **24 小时**，单机约 **38 小时**。

## 6. 汇合：三折结果怎么拼

每折的 `holdout` 正好是该折的 1/3 训练集（17,132 张），三折合起来覆盖全部 51,396 张，所以 OOF 是**干净的拼接**，不需要加权。

把 B 的产物拷回 A：

```bash
robocopy \\B_HOST\D$\computer_competition\artifacts\plan3\pilot400-rfm448-local-speed-v2-f2 ^
  E:\computer_competition\artifacts\plan3\pilot400-rfm448-local-speed-v2-f2 /E
```

需要的文件（其余可丢）：

```
status.json        ← complete 必须为 true，且 last_complete_epoch = 24 或早停轮
history.json       ← 每轮 loss / holdout 指标 / 选中 raw 还是 ema
holdout.csv        ← 17,132 行预测，OOF 拼接用
holdout.json       ← 完整指标与签名
model.pt           ← 权重 + metadata（含 fold / data_fingerprint / fold_fingerprint）
signature.json     ← 溯源
local_manifest.json← 逐文件 sha256 清单，用于完整性复核
```

拼之前先验：

1. 三份 `model.pt` 的 `metadata.data_fingerprint` 全等于 `917ca8a7...`
2. 三份 `metadata.fold_fingerprint` 全等于 `30cf96ed...`
3. 三份 `config` 字段完全一致（这是 `--pin-config` 要保证的事）
4. 三份 `holdout.csv` 的 `Image_name` 集合两两无交集，并集 = 51,396

任何一条不满足，就**不能**拼成 OOF，也不能和 Green 0.9542 / P1 0.9733 做对比。

## 7. 禁止事项

1. **不要改 A 上的 `scripts/plan3_local.py`、`plan3/*.py`、`scripts/plan3-local-profile.py`、`configs/plan3/rfm448-local-speed-v2.json`、`weights/`、`artifacts/audit/`**。这些直接参与 fold0 的续跑身份校验（`runner_sha256`、`code_sha256`、`config`、`pretrained_sha256`），改了 fold0 就续不上，12 小时白跑。
2. **不要在 B 上跑不加 `--fold` 和 `--qualify-only` 的 `finish-plan3-local-qualification.py`**。默认行为是 fold0 且跑完就开训，会和 A 撞车。
3. **不要拷 `artifacts/plan3_cache`**。缓存文件名由「行集 + data_fingerprint + 预处理配方」哈希得出，折不同就是不同文件。
4. **不要用 B 的 `qualification.json` 去启动 A 的作业**，反之亦然。workers 是本机实测值。
5. **不要为了让 B 跑起来而放宽 `--pin-config`**。跑不动 b4+gc 就换机器，混配方比慢更糟。

## 8. 备选：如果 B 是弱 GPU

如果 B 的稳态速度明显低于 A（比如 <15 张/秒），双机的边际收益很小，不值得为它付 33 GB 传输 + 85 分钟资格的代价。这时更划算的三条路：

1. **降低轮数上限**：`configs/plan3/rfm448-local-speed-v2.json` 的 `epochs` 从 24 降到 16。单折从 12h 降到 8h，三折约 24h 单机可完成。代价是少一个比较点，但早停耐心 4 轮本来也常在 18–20 轮触发。
2. **先只跑两折**：fold0 + fold1，拿到 2/3 OOF 的近似结论，再决定要不要补 fold2。磁盘也刚好够（2×30.9 GB + 33 GB 数据 ≈ 95 GB，需先清 E 盘）。
3. **彻底放弃 Kaggle 线**：实测 2.06 张/秒（T4 双卡没并行起来），8 小时会话连一轮都跑不完，比 A 慢 12 倍。这条线已经没有复活价值，建议停掉回收进程并归档那 778 MB 结果包。
