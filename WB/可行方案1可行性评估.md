## 一·补：先修正一个关键数字

《可行方案1》文档写"榜首 AUROC 0.998"。但 `实验记录.md` 第 64 行的原始记录是：

> 用户反馈当前线上分数 92.48、同一挑战赛榜首 **99.02**，显示分差为 6.54。

**榜首是 0.9902，不是 0.998。** 方案文档把 99.02 误抄成 0.998，这个误差会系统性扭曲后续判断（0.998 意味着"要消除 92.5% 错排"，0.9902 意味着 62.5%）。

这个更正有双向影响：

**对方案有利的一面**：0.9902 是**真实存在的已达成结果**。说明这个任务的 0.99 不是数据天花板问题——有人在这个评测集上做到了。所以"能不能到 0.99"的答案不是"不可能"，而是"要靠对的方法和足够的容量"。

**对方案不利的一面**：0.9902 是我们的**追赶目标**，而不是一个可以打折的参照。我们 0.9733（fold0）距它 0.017，而方案1 的机制强度约值 0.005。**目标没变低，但差距是实打实的。**

另外，此前记忆里已有一条独立结论值得并读：

> 现有资源（单台 4060 8GB）最乐观落点 0.978–0.985；0.99+ 需要 ViT-L 级容量、更高分辨率或外部数据。

**方案1 的定位裁图，正好属于这三条路径里的"更高分辨率"**。所以方向没错——它是一条已被识别为可行的路径之一。问题在于：单靠它一条，量级不够。

## 一、结论

**方案1 的方向是对的，但"0.99+"在当前证据下不成立，可信度低。**

更准确地说，问题不在"方案对不对"，而在**目标与差距的量级不匹配**：

- 从 P1 的 0.9733 到 0.99，需要净消除 **62.5%** 的剩余错排（152,412 / 243,934 对）。
- 我们已经发生过的那次最大跨越（Green → P1：主干从 ViT-S 换成 ViT-B，宽度 ×4，冻结改全微调，DINOv2 换 DINOv3），只消除了 Green 错误的 **41%**。
- 也就是说：**要达成 0.99 的那一步，必须比"换掉整个主干"更大**。而方案1 的增量是"定位 + 局部视图 + 排序损失 + 小集成"，四项里没有一项是主干级升级。

所以我的判断是：

| 目标 | 判断 | 说明 |
|---|---|---|
| 0.99+（≈榜首 0.9902） | **低可信** | 需要比"换主干"更大的单次跨越，方案1 的机制强度不足以支撑 |
| 0.98 左右（+0.007） | **中等** | 局部视图 + 排序 + 集成合起来有机会，但需实测 |
| 相对 P1 的增量 | **+0.003 ~ +0.008** | 不是方案隐含的 +0.017 |

## 二、差距的算术：这不是"再改一点"，是"再改一大截"

用 `artifacts/p1p2/p1_global/fold0/holdout.csv` 复算（P=552，N=16,580，P×N=9,152,160）：

| 项 | 数值 |
|---|---|
| P1 fold0 AUROC | 0.9733468383 |
| 当前错排 D | 243,934 |
| 达 0.99 允许的 D 上界 | 91,522 |
| **需净消除** | **152,412 对（62.48%）** |
| 等价于"从最低位完全翻正"的阳性数 | 9.2 张 |
| 实际需完全修正的"最差阳性" | **约 50 张**（fix top50 → 0.9903） |

错排集中度（与《可行方案1》文档完全一致，已独立复算验证）：

| 取样 | 占全部错排 |
|---|---:|
| 前 10 张阳性 | 27.04% |
| 前 20 张阳性 | 40.41% |
| 前 30 张阳性 | 50.52% |
| 前 50 张阳性 | 63.69% |
| 前 100 张阳性 | 81.80% |
| 前 100 张阴性 | 13.14% |

**关键点**：需要把约 50 张阳性（占阳性 9%）从"排在约 40% 阴性之下"整体推到"排在几乎全部 16,580 张阴性之上"。这是**类别性的翻转**，不是边际微调。

### 已实现的单次跨越 vs 需要的跨越

| 跨越 | 错排消除 | 占基线错误比例 |
|---|---:|---:|
| Green 0.9548 → P1 0.9733（换主干 + 全微调） | 169,685 对 | 41.0% |
| 三模型最优集成（本次实测） | 21,500 对 | 8.8% |
| **P1 → 0.99（目标）** | **152,412 对** | **62.5%** |

**要达 0.99，需要的互补收益是"三模型最优集成"的约 7 倍。**

## 三、四项检验（本次实算，不是推理）

### 检验 1：多模型互补性到底值多少？

在 fold0 上把三个**真正不同**的模型做秩平均，权重在**评测折本身上**搜索（因此结果偏乐观）：

| 组合 | AUROC | 错排 |
|---|---:|---:|
| Green 微调（ViT-S/14 @392） | 0.9548 | 413,619 |
| RFM 冻结（ViT-B/16 @336） | 0.9495 | 462,402 |
| P1（ViT-B 全微调） | 0.9733 | 243,934 |
| 均匀平均 G+P1 | 0.9727 | 249,742 ← **比 P1 单独还差** |
| 均匀平均 G+R+P1 | 0.9727 | 249,742 |
| **最优权重 G+R+P1（折内拟合）** | **0.9757** | 222,434 |

**结论**：三个架构、预训练域、训练策略都不同的模型，把互补性榨干（且偷看了评测折），只值 **+0.0024**。

边界说明：这是"多模型"而非"多视图"的测量。同一模型看不同输入（全图/近局部/宽局部）理论上互补性可能更强，因为输入信息不同。但这也说明：**靠"再加一个成员"这条路，在本数据上的价格是 0.002–0.003 量级，不是 0.017。**

### 检验 2：剩余错误是不是"模型各自不同"的？

| 指标 | 结果 |
|---|---|
| 最差 100 阳性，P1 与 Green 重叠 | **58 / 100** |
| 最差 100 阳性，P1 与 RFM 重叠 | **62 / 100** |
| 三个模型都判为最差的 | **40 / 100** |
| 阳性内部 Spearman（P1 vs Green / P1 vs RFM / Green vs RFM） | 0.717 / 0.761 / 0.680 |
| 最差 100 阳性的中位 fneg（P1 / Green / RFM） | 0.075 / 0.078 / 0.127 |

**结论**：残差错误**高度共享**，不是各模型各有各的盲区。这正是"集成收益小"的成因，也直接削弱"再加一个视图就能修正"的假设。

**同时有一个对方案1 有利的发现**：没有任何阳性落在"低于 40% 阴性"之外（`frac_pos_fneg>0.4_in_all3 = 0`）。也就是说，**不存在灾难性错标或完全无信息的阳性**，剩余错误全是"轻微错位"。这说明：
- 标签质量大概率没问题（不是错标问题）；
- 剩余差距是"证据不足"而非"证据矛盾"——**机制上确实还有可补的空间**；
- 但每个样本要爬过 1,000+ 张阴性，边际成本高。

### 检验 3：分辨率是不是瓶颈？（方案1 核心机制的直接检验）

方案1 的核心假设是"提高视盘有效分辨率能带来新信息"。如果成立，难阳性应该系统性地分辨率更低。

| 分组 | n | 中位像素 | 中位边长 |
|---|---:|---:|---:|
| 难阳性（P1 最差 20%） | 111 | 6.02 MP | 2976×2136 |
| 中位阳性 | 312 | 7.96 MP | 3456×2304 |
| 易阳性（P1 最好 20%） | 129 | 7.96 MP | 3456×2304 |
| 全部阴性（抽样 1200） | 1200 | 5.29 MP | 2736×2056 |

- 难阳性 vs 易阳性：Mann-Whitney **p = 0.329** → **不显著**
- 阳性内部 Spearman(百万像素, P1 分数) = 0.047，**p = 0.272** → **无相关**
- 阴性内部 Spearman = 0.081，p = 0.005 → 极弱

**结论**：**没有观察到"分辨率越低越难"的证据。** 这是对方案1 核心机制最直接的反证。

诚实的边界：全图像素数 ≠ 视盘占的像素数（还取决于 FOV 占比与取景）。定位裁剪改变的是后者。所以这不是决定性反驳，但它是**方案1 唯一能低成本先验检验的机制，而它没有通过**。要真正验证，必须实测"定位裁图后的分类增益"——那就要花预算。

### 检验 4：官方 valid 上的测量精度（决定"摸到 0.99"能不能当证据）

official valid：5,849 张，阳性 191。按 Hanley-McNeil：

| AUROC 真值 | 标准误 | 95% 区间半宽 |
|---|---:|---:|
| 0.99 | 0.0051 | ±0.010 |
| 0.973 | 0.0083 | ±0.016 |

**结论**：official valid 上"0.99"和"0.98"只差 2 个标准误。**在 5,849 张、191 阳性上，不要把小数点后第二位的差异当成真实增益。** 任何"我们到 0.99 了"的说法，都需要至少另一折或另一个种子确认。

## 四、方案1 各组成部分逐条评估

| 组成部分 | 技术可行性 | 对 0.99 的贡献判断 | 主要问题 |
|---|---|---|---|
| 3.1 视盘定位 + 尺度归一化 | **高**。视盘定位本身是简单任务，200–400 标注足够训出可用定位器 | **中性**。定位器会成功，但"定位成功"≠"分类提升"。检验 3 没有支持分辨率假设 | 需核实"补充 train 内标注"是否符合赛规；标注 + 训练 + 折内隔离有隐性成本 |
| 3.2 全图 + 近局部 + 宽局部 | **中**。代码上 P2 已有五块局部 + MIL 骨架，改造成定位裁图不难 | **低–中**。检验 1/2 说明"再加视图"的边际价 0.002–0.003 | P2 首轮从未跑完，连"固定网格局部有没有用"都还没有答案 |
| 3.3 CNN / RFM 双实现 | **低（RFM）/ 中（CNN）** | — | **RFM 账本只剩 2.61h，P1 单折 @336 就要 7,073s（1.96h）**。方案1 最小比较矩阵需 4 组以上对照，RFM 上做不完 |
| 3.4 排序优化（AUC 类损失 / 难样本） | **中**。实现不难，但真实 batch=4 + 累积 8 使配对批次不自然 | **低**。BCE 在理想条件下也能学对排序，实测增益通常在 0.001–0.005 | 收益容易与"多训几轮"混淆，需严格匹配对照 |
| 3.5 少量互补集成 | **高** | **实测上限 +0.0024**（检验 1） | 这是方案里**唯一有本地实测数据**的部分，而它的实测值很低 |

**综合**：五块加起来，最乐观的加性估计是 +0.005 ~ +0.010，且各部分收益高度不独立（都指向"补信息"，而检验 1/2 说明补信息的边际价格很低）。**叠加后达到 +0.017 需要每块都打出上限且互不冲突，这个概率很低。**

## 五、被低估的硬约束

### 1. 复赛部署：3 视图基本不可行

- 官网要求：T4 单张端到端 **≤100ms**，模型总大小 **≤500MB**
- P1 单视图 model.pt 已 **245.6 MiB**（ViT-B，参数量不变，多视图不增参数）
- 但 **3 视图 = 3 次前向**。ViT-B/16@336 的 FLOPs 约为 Green（ViT-S/14@392）的 8–9 倍；而 Green 在本机 4060 单张已 **120.4ms 中位**
- 结论：三视图 ViT-B 在 T4 上 100ms 内**基本不可能**。蒸馏能压下来，但蒸馏本身会吃掉那点本来就微薄的增益
- **这意味着：即使方案1 训出 0.99，也可能交不上去。** 方案1 文档提了这条约束，但没有量化

### 2. 预算

- RFM 账本：19,398.66s / 28,800s，余 **2.61h**
- P1 单折 @336 实测 7,073s = 1.96h
- 方案1 的"定位局部是否改善 P1/P2"至少需要：全图基线（已有）+ 近局部 + 宽局部 + 组合 = 3 个新训练
- **现有余额连一个都放不下**。这不是"要不要做"的选择题，是"做不了"

### 3. 时间

- 标注 200–400 张 + 训定位器 + 改数据管线 + 3 组对照训练 + 三折验证 + 集成 + 部署优化
- 按 P1 单折 1.96h 计，3 组对照 × 3 折 = 17.6h 纯 RFM 训练，加 CNN 路线另算
- 双机并行也压不到"今天之内出结论"

## 六、建议的动作顺序（按性价比排序）

### 第 0 步（今天就能做，成本几分钟，优先级最高）

**把 P1 的 fold0 模型跑一次 official valid。**

理由：**P1 从未在 official valid 上评测过**（目前只有 fold0 内部验证）。而已知 official valid 系统性偏乐观——Green 冻结版 OOF 0.9188，official valid 0.9242（+0.005）。

如果 P1 在 valid 上是 0.978 而不是 0.973，那么"到 0.99"的真实差距是 +0.012 而不是 +0.017，整个可行性判断要重写。**在不知道真实差距的情况下讨论方案，是在解一个可能设错的目标。**

### 第 1 步（低成本，高信息量）

**先把 P2 的第一轮跑完。** 理由：P2 已经实现了"全图 + 5 局部块 + MIL"，它**就是方案1 的 3.2 节去掉定位器**。如果 P2 连"固定网格局部"都打不过 P1，那么"把固定网格换成定位裁图"这个增量就更难成立——而定位器 + 标注的成本远高于跑完 P2。

**P2 是方案1 的免费前置实验。** 现在跳过它直接做标注和定位器，等于花钱买一个可以用已有代码先排除的答案。

### 第 2 步（只有前两步都正向才做）

用 CNN 路线做定位裁图（同事机器，不占 RFM 预算）。CNN 单视图 512 输入的算力远低于 ViT-B 三视图，也是唯一可能在 T4 上达标的路线。

### 不建议现在做

- RFM 上的多视图（预算不够，且部署不达标）
- 200–400 张标注（在 P2 出结果前，无法判断值不值得）
- AUC 排序损失（增益量级 0.001–0.005，不解决 0.017 的问题）

## 七、什么证据会让我改变结论

**上调**：
- P1 在 official valid 上 ≥ 0.978（说明真实差距只有 +0.012）
- P2 跑完后显著优于 P1（说明局部视图真的有 +0.01 级增益，那定位裁图就可能再叠一层）
- 定位裁图在 CNN 上、同预算对照下带来 > +0.008

**下调**：
- P1 在 valid 上 ≤ 0.975（差距 > 0.015）
- P2 与 P1 持平或更差（局部视图机制被证伪）
- 定位裁图增益 < +0.003，或只在单折出现

## 八、一句话回答

**方案1 是一套机制清楚、方向也对的改进（定位裁图正是此前识别出的三条 0.99 路径之一），但它解决的是"再涨 0.005"的问题，不是"再涨 0.017"的问题。0.99 不是靠再补一个机制能达到的，需要的是比"换主干"更大的一次跨越——而目前没有任何证据表明方案1 提供了这种量级的增益。**

**在花掉唯一剩下的 2.61 小时预算之前，先把 P1 放上 official valid、把 P2 跑完。这两件事比方案1 里的任何一项都更该先做。**
